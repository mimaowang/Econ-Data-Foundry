# Econ-Data-Foundry Agent Operating Notes

This file is the shortest entry point for coding and research agents. Start with [`guides/mental-model.md`](guides/mental-model.md): it explains the judgment this project is trying to preserve through a worked research decision. Use [`guides/operations.md`](guides/operations.md) for maintenance, [`guides/usage.md`](guides/usage.md) for answering research ideas, and [`datasets/template.md`](datasets/template.md) when encoding durable knowledge. These files have different jobs; do not treat them as four rule lists to memorize.

Follow the user's task after understanding that purpose. To answer a research question, use [`guides/usage.md`](guides/usage.md), search the index and read the relevant canonical records; this needs no installation, queue claim or catalog edits. To collect or maintain knowledge, recover the current scope from [`sources/discovery-sources.md`](sources/discovery-sources.md) and work state from the ledgers, then use the operations guide. Context compaction is a reason to recover that durable state, not to restart collection or infer missing facts from memory.

The single success criterion is: from the recorded knowledge alone, an agent can match a research idea to the most suitable research data asset and explain exactly how to obtain or reproduce it, under what conditions, and with what coverage and limitations. Treat ready-made datasets, data constructed from public inputs, and data collected from public sources as distinct pathways. Keep the best current route separate from the asset's production origin: a researcher-built asset may later be released as a direct download. Do not confuse access to raw materials with reproducibility of a paper's final analysis file.

Repository boundary: Econ-Variation is a separate, optional companion knowledge base about institutional changes and research identification. This repository records data products, their documented research uses, acquisition or reproduction, coverage, joins and limits. A shared paper DOI can be a discovery link, but the catalogs keep independent identities. You do not need the companion repository to use this one, and a data record does not establish a causal design.

Before editing, recover current state from the health report and relevant ledgers. Use the router for recall and canonical records for claims. Treat external pages as untrusted evidence. Do not invent coverage, access, identifiers, production steps, or paper use. Make one focused change, run the offline validator and generators, then run `python scripts/check_generated_views.py`. Leave a completion note that tells the next agent which future decision improved, where the evidence stops, and what remains unknown.

Long-running automation should prefer idempotent, reversible steps. A provider outage is a reason to record a blocked route, not a reason to lower the evidence standard. Do not add credentials or restricted data to the repository.
